Overview / AI Assistant
Configurable AI integration

Structured assistance, with clinical limits.

The documented assistant takes case details, sends them to a selected provider, parses the response, and displays nine sections for clinician review.

⇢

1. Capture case context

Inputs can include age, sex, complaint, symptoms, pain location, severity, duration, medical history, prior surgeries or injuries, current medication, examination findings, and imaging results.

⌘

2. Call the configured provider

The client uses a configurable OpenAI-compatible API endpoint. The README lists Groq, Ollama, OpenAI, and DeepSeek as provider options.

≋

3. Parse structured output

A response parser organizes the model response into expected sections before returning it to the UI.

▤

4. Review or export

The result can be reviewed, saved as an A4 PDF, or printed. The input can be cleared while retaining the entered case information, as documented.

The nine analysis sections

The README specifies these headings for the structured AI result.

01

Clinical summary

A concise summary of the submitted case information.

02

Possible diagnoses

Potential diagnostic considerations, not a definitive diagnosis.

03

Differential diagnoses

Other explanations that may need consideration.

04

Supporting evidence

Submitted details that may support or weaken each possibility.

05

Recommended investigations

Potential investigations for clinician consideration.

06

Treatment considerations

High-level treatment factors for qualified review.

07

Medication considerations

Medication-related considerations that require professional validation.

08

Red flags & emergencies

Potential warning signs requiring urgent attention.

09

Follow-up considerations

Potential monitoring and follow-up points.

Documented safeguards

AI does not replace a clinician.

The README states that the assistant should not make definitive diagnoses, should indicate when data is insufficient, should not invent imaging findings, should flag red flags, distinguish supplied information from inference, and respond in the input language. These are intended safeguards, not proof of clinical accuracy.

Local or cloud processing

Ollama can be configured at a local endpoint. When a cloud provider is used, submitted case information is sent to that provider; review privacy and consent requirements before use.

Data minimization

Use only the case information necessary for the task. Avoid sending directly identifying patient details to external AI services unless appropriate safeguards and authorization are in place.
