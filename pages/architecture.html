Overview / Architecture
System design

Clear boundaries. Separable responsibilities.

The README documents a layered architecture that separates presentation, business logic, data access, models, and persistence.

The five core layers

Read from top to bottom to follow the main application data path.

UI Layer · PySide6Displays pages and invokes application services; no business logic in the UI.
↓
Services LayerBusiness rules, validation, and coordination between repositories.
↓
Repositories LayerCRUD operations and database queries, isolated from business logic.
↓
Models Layer · SQLAlchemy 2.0Table definitions, relationships, and indexes.
↓
SQLite · clinic.dbLocal database file used for persistence.

Why these boundaries matter

Separation of concerns

Each layer has a defined responsibility. UI changes should not require moving database query logic into screen code.

Repository pattern

Data access is isolated behind repositories, giving services a focused place to request and update records.

Dependency injection

The README says services are passed to the UI from main.py, instead of being constructed throughout the UI.

AI provider abstraction

The AI integration is designed so providers can be switched through configuration without rewriting the rest of the app's flow.
